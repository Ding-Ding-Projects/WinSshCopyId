# Server manager services

The server services expose immutable instance and target records, an atomic local registry, lossless property editing, official Java metadata discovery, reviewable lifecycle plans, and verified directory backup/restore for explicitly adopted stopped local-process instances. Construction and discovery never launch a server or adopt existing processes.

## Source discovery and capabilities

`ServerCatalogue.RefreshJavaAsync` reads the official Mojang version manifest, retaining every returned release, snapshot and historical entry. A selected entry is resolved only after its metadata SHA-1 matches. Missing dedicated-server downloads return unavailable; missing Java runtime information remains unknown. Returned download descriptors include exact byte count and digest. The catalog checks bounded response sizes, timeouts, approved HTTPS origins and the final response URI. The default constructor disables redirects and proxies. The injected-client constructor exists for controlled transports and tests; callers must disable redirects on any injected live HTTP client because checking a final URI cannot prevent that client from already following an unauthorized redirect.

The snapshot deliberately reports incomplete coverage: Java metadata entries do not prove that every server distribution exists. Historical Bedrock packages, third-party flavors, plugins, mods, packs and version-specific setting descriptors require additional source and runtime acceptance. No default list is represented as exhaustive.

`JavaServerProvisioner.CreateAsync` turns one selected resolved official Java distribution into a new instance directory only after explicit EULA consent. It downloads from the admitted official origin with bounded duration and exact expected length, verifies the official metadata SHA-1 and computes a local SHA-256, writes explicit EULA/online-mode/port settings, and atomically promotes its own staging directory. Existing destination directories are never replaced and no world is migrated. It returns the exact Java-major requirement when known; acquiring/admitting that Java runtime is separate and it never launches a server. Fake-byte tests prove exact transfer, existing-directory preservation and missing-consent rejection without obtaining a real distribution.

## Configuration and persistence

`ServerProperties` preserves comments, unknown properties, ordering and original newline style while applying typed validated port changes. It rejects line injection. This is literal `key=value` support, not a full Java-properties escape/continuation implementation. `ServerRegistry` uses schema-versioned immutable records, duplicate identity checks, a 16 MiB limit and temporary-file promotion. Instance extension values survive a round trip. Private instance state belongs under the user's application-data directory, never the repository.

## Four target boundaries

The target model includes local process, local Docker, SSH process and SSH Docker. `ServerProcessAdapter` starts only adopted Java/Bedrock instances with explicit EULA consent, absolute executable paths and matching distribution/runtime hashes. It retains read leases during launch, the exact process object, PID and start time. Output is drained in bounded chunks without an accumulating log. Readiness remains distinct from an alive process. Graceful stop writes the literal server `stop` command to the retained process stdin and waits up to the selected bounded deadline. A timeout retains the process unless the caller explicitly selects termination of that exact owned process tree. Existing processes are never adopted from a PID.

`ServerDockerAdapter` inspects an already present approved immutable image, then creates and starts a container with an exact instance label, nonlinked instance mount, loopback-only published TCP/UDP ports, memory/PID limits, dropped capabilities and no-new-privileges. It never pulls images. Every observation and stop checks the exact container ID, instance label and image again. Stop requests infinite daemon grace, avoiding implicit forced termination, while CLI observation stays time bounded. A timed-out CLI does not mean the container stopped. Containers are retained after stopping.

`ServerCommandExecutor` admits only a digest-verified absolute CLI, uses typed argument lists without a shell, limits UTF-8 output bytes and duration, and tears down only its own bounded CLI process tree. `ServerSshAdapter` supports both SSH target kinds through an injected `IApprovedServerSshTransport`. Requests contain structured data, approved host-key identity and a session receipt. Responses must match host, request and instance identities. Read-only discovery cannot adopt a session. The application's actual SSH service must implement the remote versioned-agent transport and verify the host key before authentication. This implementation never generates a remote shell string or supplies credentials.

`ServerLifecyclePlanner` remains a conservative preview API; its disabled boundaries are distinct from the explicit adapters. A preview does not launch anything. Runtime health, real daemon/SSH behavior, reconnect and exact distribution compatibility need acceptance before the GUI claims operational support.

## Backup and restore

Backups require adopted local-process instances and fresh stopped observations. Links and reparse points are rejected. Storage is bounded to a configurable 64 GiB and one million entries by default. Each copied member has a SHA-256 receipt. Backups are promoted only after successful creation. Restore verifies all members, stages and independently verifies the restored bytes, then renames the old instance directory into a retained rollback directory before promotion. Cancellation before promotion leaves the existing directory in place. The original rollback directory is never automatically removed. These are file operations, not proof of a live server's stopped state; the owner must supply a trustworthy current observation.

## Verification and remaining work

The dependency-free `tests/WinSshCopyId.Tools.Tests` executable checks property preservation/injection rejection, registry persistence, blocked unapproved launches, untrusted SSH, backup/restore/rollback byte preservation, tampered-backup rejection, running-instance rejection and Java metadata digest validation with a fake HTTP transport. A bounded test child proves owned process start/observe/stdin-stop. Fake Docker responses prove typed lifecycle wiring, and a mismatched SSH host receipt is rejected. No real server or service launches. Actual Java/Bedrock runtime matrices, real Docker/SSH execution, plugin/mod installation, world management, upgrades, remote backups, networking, real GUI acceptance and complete historical compatibility remain unverified and incomplete.
