# Workspace security services

This package-free .NET 8 domain layer provides RFC 4226 HOTP and RFC 6238 TOTP with SHA-1, SHA-256 and SHA-512, six to eight digits and configurable positive periods. Base32 parsing rejects invalid symbols, lengths, padding and nonzero trailing bits. Verification permits an explicitly bounded clock tolerance. The caller must provide a trustworthy clock and disclose detected clock skew.

`VaultDelegates` injects Get, Set and Delete operations. Authenticator registration confirms a current code before storing the decoded secret under a random stable reference. Entry metadata contains only a reference. The production adapter must supply the operating-system credential vault; the synthetic suite uses an in-memory dictionary and never touches real credentials. Stored secrets have no reveal or ordinary export API. QR generation, URI parsing, import routes, user interface, history and privileged export confirmation are not implemented by this domain layer.

`ToyLockEngine` creates independent target credentials for six ordered policies. PIN and password verifiers use random salts and PBKDF2-SHA256 with 210,000 iterations; TOTP material is stored only through the vault. Launch/load starts locked, explicit relock and duration expiry apply independently, and disposal invalidates the engine. Callers must route every protected operation and input path through the same instance. These are ornamental local locks, not an operating-system security boundary. Metadata persistence and operating-system vault lifetime remain the adapter's responsibility. A complete ordered factor set is submitted atomically; partial-factor wizard state is not exposed.

Failures share a target budget. Exhaustion starts an exponentially increasing wait capped at one hour. Serving or solving the wait restores the same attempt allotment. Solving never unlocks the target or resets escalation. A successful credential authentication resets consecutive-failure escalation. The host adapter must atomically persist `ToyLockEngine.ExportBudgets()` and `UnlockLadder.ExportBudgets()` after each mutation, load lock definitions, and import both snapshots before accepting input after restart. Imports reject future snapshots (clock rollback), invalid ranges, duplicate targets and invalid skip timestamps. Snapshots contain no credentials or active authentication state. Unlocked state and outstanding challenge nonces are deliberately never restored. Storage integrity, atomic writes and fail-closed handling of missing/corrupt snapshots remain the host adapter responsibility; explicit export/import alone does not prove production persistence.

`UnlockLadder` owns random single-use expiring challenges. Five wrong dish selections advance to ten sums, one wrong sum advances to a timed mole round, and a lost round leaves only the clock. School mode begins with sums. Up to three successful skips per target rolling hour are allowed. Mole hits must arrive individually through `Hit`; the engine stamps their time, checks visibility and cell, and counts each mole once. Submitted client timestamp lists cannot win. Final submission before the complete round duration fails. All state is local, so a browser consumer needs a privileged host adapter rather than copying this authority into page script.

Verification uses the standalone console project at `tests/WinSshCopyId.Workspace.Security.Tests`. Published RFC vectors cover all three algorithms at six and eight digits; additional synthetic checks cover base32 rejection, six policies, target isolation, relock, duration, budget, replay and early-round rejection. This is domain verification only. It does not prove graphical workflows, QR scanning, accessibility, real vault persistence, production restart persistence or packaged runtime behavior.

Target identities are bounded to 256 characters, engines to 1,024 targets, and supplied credentials to 1,024 characters before expensive derivation. Loaded references are validated, unique per factor and defensively copied. Derived hash arrays are cleared. The ladder supports disposal, clearing active challenges and budgets. Instances are single-thread-owned; a host receiving concurrent calls must serialize them.
