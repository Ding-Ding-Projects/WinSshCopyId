# Settings, search and scheduling

`WorkspaceSettingsStore` stores schema version 1 in injected private application storage. `DirectoryPrivateStorage` writes a unique temporary file, flushes it, then atomically replaces the previous file while retaining a backup. Loading validates the primary record and then the backup. Unsupported or corrupt records produce explicit defaults and a warning. The display name is user-editable while `WorkspaceSettings.ProductIdentity` remains immutable. The default accent is blue, both humor levels are 5, narration is opt-in, voice identifiers are independently stored for each language, and the five attention modes are independently off.

`WorkspaceSessionStore` persists tabs, groups and snippets. `WorkspaceSession` provides open, close and reorder/group actions; a locked tab cannot be closed. View models must keep a separate `SearchQuery` for each search surface, including menus, pickers and the adjacent anchored regular-expression workbench. These services do not render those controls.

`WorkspaceSearch` uses the actual .NET regex engine. Plain text is the default; regex mode enables groups, captures, lookarounds, backreferences, Unicode classes and replacement groups. Flags cover case sensitivity, multiline, singleline and whitespace mode. Inputs are limited to 262,144 characters, patterns/replacements to 4,096, matches to 1,000, execution to 100 milliseconds per engine invocation, and replacement output to 262,144 characters. Invalid expressions and timeouts return validation results. A limited preview replaces only the returned matches and explicitly reports `Limited`.

Schedules use version 1, stable identifiers, at most 100 rules, an explicit timezone and optional inclusive start/end dates. Start time is inclusive and end time exclusive. Equal times mean a full day. An empty weekday set means every day. The after-midnight part of a crossing interval belongs to its starting weekday/date. UTC instants are converted through `TimeZoneInfo`; repeated daylight-saving times follow their actual local clock reading and nonexistent local times never occur. Later enabled matching rules override earlier fields. The base settings are never modified by evaluation. `ScheduleStore` persists the versioned rules.

External HTTPS settings accept `{ "Version": 1, "Values": { "Theme": 2 } }` using the public `SettingsOverride` property names and numeric enum values. Unknown fields are rejected. Sources have a 10-second timeout and a 64-KiB response limit. Redirects, cookies, proxies, embedded URL credentials and URL queries are rejected. DNS is resolved and the validated public addresses are pinned to the connection. Private-LAN Home Assistant requires an explicitly supplied `PrivateSettingsTarget` matching the exact authority and a bounded set of exact approved addresses. Resolved addresses must all match that list and are pinned to the connection; an ordinary schedule cannot authorize its own private target. HTTPS certificate validation remains enabled. No ambient credentials are used.

Home Assistant supports `binary_sensor` and `input_boolean` entities. The schedule stores only a credential reference; `ExternalSettingsSource` receives a delegate backed by the application's credential service. `on` returns the configured override, `off` returns no override, and missing credentials or unknown states produce an explicit exception. `ScheduleCoordinator` cancels superseded work, checks a monotonic generation before applying any response, bounds a complete refresh to 15 seconds and allows background intervals from 30 seconds to one hour. Ending a schedule restores the unchanged base settings. A current refresh failure or timeout exposes base/local settings and unavailable rule identifiers, never silently persisting an external value. UI callers provide the localized non-blocking recovery notification from that result. Disposal cancels the loop and current work.

The package-free console checks use SDK 8.0.424 and test actual service behavior. They are independent of the product's required root build entrypoints and do not prove UI, accessibility or installer acceptance.
