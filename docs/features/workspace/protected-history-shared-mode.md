# Protected snapshots and shared mode

`ProtectedWorkspaceHistory` stores encrypted JSON snapshots in an explicitly supplied, isolated application-data directory. It uses AES-256-GCM with fresh nonces; the stable record identifier is authenticated as associated data, so delete and restore do not bind encryption to a replaceable database row. Its encryption key and independently verified PBKDF2 history credential live behind injected platform-credential delegates. Opening history returns a short-lived disposable access object. Manager disposal clears its active access keys. No real credential store is used by tests.

Each saved snapshot invokes genuine local Git staging and commit. Browse lists only successfully committed, unmodified revision files. Read and diff require an active history access object. Restoring applies the selected snapshot through an injected application callback and records a new `restored` revision referencing the original. If the callback fails, the exception is visible. If recording fails after a successful callback, the result explicitly says history was not recorded; the live restoration must not be described as backed up. Original revisions are never reset or rewritten.

Labels and retention archives are new encrypted revisions. `ArchiveAsync` creates an archive index under a validated keep-count and keep-days policy; encrypted originals and Git objects remain retained. It is logical archival, not physical reclamation or destructive pruning. Redacted export includes only allowlisted action/kind identifiers, generated identifiers, timestamps and an omission disclosure. Snapshot content, labels, credentials, replacement payloads, file metadata and source paths are excluded. Snapshot JSON is limited to 700,000 bytes. The caller must exclude local replacement caches from all snapshots and present decrypted diff text only inside the authenticated private history surface.

`SharedSchoolMode` implements the existing application-catalog shared protocol at the platform roaming application-data directory's `Ding-Ding-Projects/global/school-mode.v1.json`. Stored schema version 2 contains `recordId`, monotonically increasing `revision`, `enabled`, `displayName`, `unlockKind`, `salt` and `verifier`. The verifier uses scrypt N=16384, r=8, p=1, matching the existing consumer; a synthetic cross-engine vector checks compatibility. Public snapshots contain only state, never the salt or verifier. Existing unsupported passkey records remain readable but cannot be unlocked by this PIN/password backend.

Writes acquire the same sibling `.lock` file exclusively with bounded retries, check the expected record identity/revision, and atomically replace the record. An active or abandoned lock is retained rather than stolen. Concurrent edits produce a reload-required result. No destructive recovery or automatic credential reset occurs. An older terminal-specific protocol uses a different directory and shape; this service deliberately does not silently migrate, overwrite or claim to synchronize that older protocol.

The watcher starts at the nearest existing ancestor and moves to the shared directory once present. Filesystem changes immediately mark the presentation unknown while a fresh read proceeds. A two-second reconciliation poll supports directory creation and watcher recovery. Missing state is a confirmed default only after a successful watched read; corrupt, unsupported or unavailable state remains restricted with a visible reason. The user's chosen name is preserved in state. The effective projection forces English and serious copy while enabled or unknown, suppresses personal replacement/playful capability availability, and preserves the original settings for restoration. The UI must omit suppressed controls and use the chosen display name throughout. This is a user-experience preference lock, not a security boundary.

`WorkspaceSecuritySession` serializes target-lock and ladder operations, stores definitions and both restart-budget snapshots atomically under AES-GCM, and keeps its key only in the injected credential vault. Corrupt state or missing keys makes the adapter unavailable; a persistence failure disables further protected actions until reload. Previously unlocked state and outstanding challenges never survive restart. The UI must use this adapter for every protected action, rather than directly invoking the lower-level engines and skipping persistence.

## 廣東話說明

歷史快照會先加密，再由真正的本機 Git 記錄。睇歷史、比較同還原都要先通過歷史本身的憑證；還原會新增紀錄，唔會改寫舊紀錄。普通匯出只保留已篩選的操作資料，唔會帶走快照內容或憑證。保留政策目前建立封存索引，唔會假裝已經刪除舊物件或釋放空間。

共用模式沿用現有目錄程式的版本二格式，名稱同開關會透過監看及有界限的定期核對同步。資料讀唔到、損壞或監看出問題時，介面維持受限顯示並講清楚原因，唔會當作已關閉。使用者原本的語言同外觀設定會保留，模式關閉之後先恢復。每個操作目標的鎖同等待次數另外儲存，重新開啟程式唔會送返額外嘗試次數。
