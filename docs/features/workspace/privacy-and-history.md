# Local replacement import and history boundaries

The generic local import schema is an object containing exactly `schemaVersion: 1` and `entries`, an object of original strings to replacement strings. Its bounds are 256 KiB UTF-8, depth 8, keys of 1 to 160 Unicode code points and values up to 1,000 code points. Duplicate keys, unsupported versions, unexpected properties, non-string values, unsafe object keys and prohibited controls are rejected before applying or caching any entry. The inventory is dynamic with no fixed entry count. The loader contains no supplied mappings, examples derived from private data, or source-file metadata.

`PersonalVocabulary` caches only the validated bytes in injected private local storage. Every cache load revalidates and restores original shipped text on corruption. Invalid imports retain the last valid state. Clear removes the cache and its backup, then immediately restores original strings. Only `ApplyPrivateText` applies exact mappings at a private presentation boundary; commands, paths, external records and public output must never pass through it. Network, export, telemetry and history APIs receive no cache or source metadata.

`WorkspaceHistory` records an append-only, payload-free audit trail in an explicitly supplied isolated application-data directory. It never creates a repository inside a user's document directory unless a caller violates the constructor contract. Each successful record invokes genuine `git init`, `git add` and `git commit` through an injectable process executor; missing Git or a nonzero result is explicitly reported as not recorded. The resolver checks bundled Git first, then PATH. No synchronization or push occurs.

Only allowlisted action/kind identifiers, generated record identifiers and timestamps enter this metadata audit service. Names, hostnames, paths, credentials, replacement data and document contents are omitted by construction. The separate `ProtectedWorkspaceHistory` service implements credential-protected encrypted document snapshots, browse, diff, append-only restore, labels, logical retention archives and redacted exports, described in [Protected snapshots and shared mode](protected-history-shared-mode.md). Physical history pruning is deliberately not implemented; metadata records alone must never be described as full document recovery.

`BoundedQueue` offers thread-safe bounded operation/notification retention. Callers are responsible for supplying safe localized messages with all sensitive values removed. The narrator and notification models represent preferences and state, not platform speech or toast delivery.
